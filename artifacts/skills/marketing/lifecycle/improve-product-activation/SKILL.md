# Improve Product Activation

## Contract

Activation is an evidenced user outcome, not checklist completion. Reduce unnecessary setup while preserving informed choices, safety, accessibility, and realistic product expectations.

## Shorten the path to value

1. Define target segment, entry intent, verified value event, prerequisites, baseline cohort behavior, time-to-value, retention relationship, and major failure or abandonment states.
2. Map the first-use journey across account state, data or integration needs, empty states, permissions, guidance, errors, support, notifications, and return paths. Observe representative users when possible.
3. Remove or defer steps that do not create value, teach through meaningful action, provide realistic examples, make progress and consequences clear, and add recovery at risky boundaries.
4. Prioritize defects and hypotheses, instrument state transitions, test with guarded cohorts, and evaluate value attainment, time, downstream retention, support load, and negative outcomes.

## Validation

- The activation event is behaviorally defined and linked to later value with stated uncertainty.
- Journey findings include exact states, prerequisites, errors, and affected segments.
- Validation measures real value and durable behavior, not tutorial completion alone.

## Stop conditions

Stop when activation has no agreed definition, required data is unreliable, user testing lacks consent, or changes would bypass permissions, security, or product commitments.

## Refusals

- It does not add forced tours, fake progress, nagging, or celebratory friction without user value.
- It does not hide required setup, data use, or irreversible actions.
- It does not claim activation or retention impact without cohort evidence.
