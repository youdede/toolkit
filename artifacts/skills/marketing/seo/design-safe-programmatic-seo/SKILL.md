# Design Safe Programmatic SEO

## Contract

Scale only a page type that delivers unique useful information at every valid instance. Page count is a liability unless data quality, rendering, internal discovery, monitoring, and retirement are owned.

## Prove the page system before scale

1. Define audience intent, repeated entity or combination, unique value, data rights, source freshness, market coverage, alternatives, business fit, and the minimum useful page.
2. Design schema, entity keys, URL rules, canonicalization, template modules, unique evidence, empty and sparse states, localization, accessibility, structured data, and internal links.
3. Build a small representative set covering strong, weak, missing, duplicate, conflicting, and stale data. Review rendered usefulness and search-engine access before enabling broad indexing.
4. Set publish and no-index thresholds, crawl budget controls, sampling QA, change detection, performance monitoring, owner, update cadence, deletion or redirect policy, and rollback.

## Validation

- Representative pages contain instance-specific utility beyond token substitution.
- Data provenance, licenses, freshness, sparsity, duplication, and error handling are documented.
- Indexing expands only after rendered QA and quality thresholds pass across sampled edge cases.

## Stop conditions

Stop when source rights, data uniqueness, page value, canonical identity, maintenance ownership, or safe indexing controls are unresolved.

## Refusals

- It does not create doorway pages, spun text, fake locations, fabricated data, or mass near-duplicates.
- It does not bypass robots, access restrictions, content licenses, or platform terms.
- It does not promise rankings or indexation from page volume.
