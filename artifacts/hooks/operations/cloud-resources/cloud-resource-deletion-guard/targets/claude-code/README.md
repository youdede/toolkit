# Cloud resource deletion guard for Claude Code

This project-scoped `PreToolUse` hook recognizes direct AWS, Google Cloud (`gcloud`, `gsutil`), and Azure CLI deletion, termination, removal, undeployment, and purge verbs, including `aws s3 rm`/`rb`, `gcloud storage rm`, and Azure `delete-*` forms. Read-only list, describe, get, and show operations pass. The exported `evaluate(input)` function is pure and never contacts provider APIs.

## Refusals and limits

- The hook does not delete, recover, snapshot, enumerate, or inspect cloud resources.
- It does not infer production status from account names, resource names, prompts, or environment variables.
- It does not cover custom cloud wrappers, aliases, SDK calls, or infrastructure-as-code commands.
- It reads each command through the shared shell analysis: wrappers such as `sudo`, `doas`, `env`, `nice`, and `timeout`, `sh -c`/`bash -c`/`eval`, `xargs`, `find -exec`, and interpreter one-liners (`python -c`, `node -e`, `ruby -e`, `perl -e`, `php -r`, `deno eval`, also attached as `-c"…"` or `--eval=…`), read only among the interpreter's own options, before its script (`node app.js --eval …` runs app.js; the word after an option is read as its value, not as the script). If the program names something that can run a command (a module such as `subprocess` or `child_process`, a call such as `system`, backticks, or a dynamic name such as `getattr` or `eval`), the hook treats it as uninspectable and blocks it when the text, or the program's string literals joined with their static escapes decoded, concerns what the hook protects. In a program capable of running commands, an escape the reader does not decode with certainty or a here-document makes it block. `open` counts only where it can open a pipe (Ruby, Perl), not in Python or JavaScript; a static command in a literal gets its concrete rule. A command built at run time from pieces that do not name it is not seen. A program that names nothing of the kind passes, and its literals are data. A program the reader does not follow to the end (more than 256 literals, deep interpolation, an unterminated literal) is uninspectable too. A one-liner whose program is known only at run time counts as a form the analysis cannot follow. It does not see a command built at run time, a command inside `$(…)`, a script file, or a program that passes an argument list. A shell form the analysis cannot follow is refused only when the command text looks like a cloud CLI deletion.
- It does not accept CLI confirmation flags as proof of human authorization.
