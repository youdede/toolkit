# Changelog

All notable changes are recorded here. Versions follow Semantic Versioning; release entries are derived from reviewed pull requests and verified against the corresponding Git tag.

## Unreleased

### Added

- `npm run release:prepare` derives the next version from the Conventional Commits since the last one, turns the `Unreleased` changelog heading into it, and updates `package.json`, `package-lock.json`, `CITATION.cff`, and the generated marketplace manifests, so no release needs a hand-picked version.
- Hooks that read Bash commands can share one shell analysis (superseded before release by `shell-items.mjs` and `capability.mjs`; see Removed): `scripts/lib/shared-hook/shell.mjs` (segments and their operators, wrappers including `sudo`, `env`, `nice`, `timeout`, and `xargs`, every bash and zsh precommand modifier and reserved word that precedes a command (`coproc`, `nocorrect`, `-`, `repeat`, `builtin`, `command`, `exec -cl`, `time -p`, `!`; any other reserved word in command position is ambiguous, PR38-CODEX9-1), function definitions (`name()`, `function name`, also with newlines before the `{`, PR38-CODEX11-3), whose `{ … }` body runs only where the name is later called in the same scope or a subshell inside it (a definition made in a `( … )` or `$( … )` subshell ends with it, a `{ … }` group shares the scope, PR38-CODEX13-3) in a way that looks up functions in bash or zsh: bare, or after `!`, `time`, `noglob`, `nocorrect`, `-`, a reserved word, or `exec` (zsh `exec f` runs the function, and the hook does not know the shell, PR38-CODEX12-2), not after `command`, `builtin`, `env`, `sudo`, or another external-command wrapper, which find no function in either shell (PR38-CODEX10-2, PR38-CODEX11-2), array assignments (`arr=(…)`, `x+=(…)`, also after `declare` or `local`), whose elements are data and whose substitutions still run (PR38-CODEX10-3), `sh -c`/`bash -c`/`eval`, `find -exec`, quoting including ANSI-C `$'…'`, decoded with the bash escapes (an escape not decoded for certain makes the word dynamic), while `$"…"`, which the locale's message catalog translates at run time, is a dynamic word judged by its source text (PR38-CODEX12-1, PR38-CODEX13-2), unquoted brace words expanded statically as bash does (`n{p..p}m` is `npm`, `n{p,x}m` the two words `npm nxm`; comma lists, nesting, integer and letter sequences with a step and zero padding; invalid forms such as `{a}` stay literal, assignments are not expanded, an unquoted null result is removed as bash removes null words, so `{,npm} publish` runs `npm publish` while a quoted empty word stays (PR38-CODEX15-1), and a word past 64 results or 1024 characters, or not known for certain, stays dynamic with its expansions as its text and may match anything, so the command stays relevant to every hook, PR38-CODEX14-1, PR38-CODEX16-1; a command past the wrapper or nesting cap is likewise ambiguous and relevant), unquoted filesystem globs (`*`, `?`, `[…]`, pattern groups) treated as file names known only at run time: a glob executable (`n[p]m`) makes the command ambiguous and relevant to every hook, so every hook that judges ambiguous commands by their text blocks it; a glob argument's text lists every alternative of its bracket sets and groups, and one that may match anything (`*`, `?`, past 16 alternatives) makes an ambiguous command relevant; and a glob argument is judged by the hook's own policy, which runs on each word the glob can expand to that the policy may act on: a finite glob (only bracket sets and `@()`, `?()`, `(a|b)` groups) is expanded exactly into all its strings (`aws ec2 de[l]ete-vpc` is judged as `delete-vpc`), and any other glob is replaced by every word of the policy's vocabulary it matches (the string literals of its policy functions and the elements of its constant sets) and, for every regular expression the policy uses, by a common string found in the product of the glob's and the regular expression's automata when there is one (`aws ec2 delete-v*` meets `/^delete(?:-[a-z0-9-]+)?$/` in `delete-v`), so `terraform state r[m]`, `docker buildx imagetools cr[e]ate`, `gcloud alpha compute instances del[e]te`, and `npm -- pub[l]ish` are uninspectable while a glob that matches no policy word passes whatever precedes it (`npm --no-progress test src/*.test.js`, `docker build -f docker/*.Dockerfile .`, `aws s3 cp dist/* s3://b/`); for a protected executable (one the vocabulary names or a policy pattern matches) an option glob, a capped word, a glob or pattern it cannot read, a finite glob past 64 strings, or more than 64 combinations fails closed (PR38-CODEX15-2, PR38-CODEX16-2, PR38-CODEX17-1, PR38-CODEX17-3); this replaces the per-tool word counts and flag lists, a `(` glued to word text opens a pattern group of that word (bash extglob `@(…)`, `+(…)`, `*(…)`, `?(…)`, `!(…)`, zsh `n(p|x)m`, qualifiers `*(.)`, and zsh `=(…)`, whose text runs like `<(…)`), so the word is a dynamic glob judged with its first alternative and never split into commands (PR38-CODEX13-1), executable paths, Git global options, directory changes) and `scripts/lib/shared-hook/commit-content.mjs` (what a command's `git commit` will take). `npm run shared-hooks` copies them into each hook between `// <youdede:shared <name>>` markers, so an installed hook stays one file; `npm run check:shared-hooks`, part of `npm run check`, fails on a stale copy or a broken marker. `tests/shared-hook-shell.test.mjs` holds one probe suite for both modules, including `sudo --` and long adversarial inputs under a time limit, and runs its process probes against every hook that embeds the module. `shell-command-guard` and `commit-guard` use it.
- `scripts/lib/shared-hook/inline-script.mjs` (superseded before release by `inline.mjs`; see Removed), a third shared hook module, reads the shell commands written as string literals inside interpreter one-liners (`python -c`, `node -e`, `ruby -e`, `perl -e`, `php -r`, `deno eval`) and whole cmd programs (`cmd /c`; PowerShell is unwrapped by the shell module), so a guard can apply its rules to `python3 -c "os.system('npm publish')"`. Attached program options count too (`python3 -c"…"`, `node --eval=…`, `ruby -e"…"`, `perl -lnE'…'`, `php -r"…"`, `deno repl --eval=…`), and a program known only at run time (`python3 -c "$CODE"`, a word `xargs` supplies) is ambiguous (PR38-CODEX-1). The rule: if the program names something that can run a command, the hook treats it as uninspectable and blocks it when the text concerns what the hook protects; a command built at run time from pieces that do not name it is not seen (PR38-CODEX5-1). The program's code is read with its literals, JavaScript regular expressions, and comments removed, so a program that names nothing able to run a command (a module such as `subprocess` or `child_process`, a call such as `system` or `exec`, backticks, `%x`, `qx`, or a dynamic name such as `getattr`, `__import__`, `eval`, `require`, `send`; the list is per language, and `open` counts only where it can open a pipe, in Ruby and Perl, so Python `open('report.txt', 'w')` is file I/O, PR38-CODEX6-3) passes, and its literals are data (`python3 -c "print('npm publish')"`, `python3 -c "print('system', 'npm publish')"`). When it names one, each literal is also read as a shell command, so a static command gets its concrete rule (`perl -e 'system q Xnpm publishX'`), and the text checked for relevance includes the literals joined and decoded, so `os.system('n' 'pm publish')` and `os.system('npm pu\x62lish')` are blocked. In a program capable of running commands, an escape the reader does not decode with certainty or a here-document makes it block: the reader trusts only backslash, quotes, sigils, `\n`, `\t`, `\r`, `\xHH`, and `\uHHHH` where the language has them, so `\o{…}`, `\N{…}`, octal, `\u{…}`, and a Ruby, Perl, or PHP here-document block (PR38-CODEX6-2, PR38-CODEX7-2, PR38-CODEX7-3); `import subprocess; subprocess.run(['ls', '-l'])` and `require('child_process').execSync('git status')` pass because they concern nothing these hooks protect. A program the reader does not follow to the end is uninspectable whatever it names: more than 256 literals, interpolation deeper than the reader rereads, or an unterminated literal (PR38-CODEX4-3). A program option followed by another option (`node -p -e …`, `node -e -p …`) keeps both candidate words, so the real program is read whichever the interpreter takes (PR38-CODEX4-2). The interpreter's options end at `--` or at its first operand (the script, `-`, a module after `python -m`, a file after `php -f`), and later words belong to the script, so `node app.js --eval …` is not a one-liner; the word after any option written without `=` is read as that option's value, never as the script, so no list of value options has to be complete and `node --inspect-publish-uid http -e …` is still a one-liner (PR38-CODEX9-2, PR38-CODEX10-1). Interpolated code (`"#{…}"`, `${…}`, Python f-strings) is reread as code. Literals are quoted strings, Python triple quotes, backticks, Ruby `%q`/`%Q`/`%x` with any delimiter and `%(…)`, `%{…}`, `%[…]`, `%<…>`, and Perl `q`/`qq`/`qx`/`qw` with any delimiter, a word character too after whitespace (`q XtextX`), paired delimiters nesting (PR38-CODEX-4, PR38-CODEX2-1, PR38-CODEX2-2, PR38-CODEX3-2 to 5, PR38-CODEX5-2). A program that builds its command at run time or passes an argument list is not seen. `tests/shared-hook-inline-script.test.mjs` holds its probes.
- The shared shell module also unwraps `doas`, `setsid`, and `pwsh`/`powershell` (`-Command`, or the first word for Windows PowerShell; `-EncodedCommand` is ambiguous), marks tokens with an unquoted `*`, `?`, or `[` as `glob`, and always moves redirections out of the tokens, in any position (`>/tmp/out npm publish` runs `npm publish`), together with their descriptor, a number or bash's `{name}` (`{fd}>/tmp/out npm publish`, whose redirection keeps the plain `>` operator and the name in `variable`, PR38-CODEX11-1), so a leading redirection is never taken for the executable; a hook that passes `{ redirections: true }` also gets them in `redirections` (`x>/etc/hosts`, `2>&1`, `&>>log`, `<.env`) and can read their targets without its own lexer, and other hooks never see them (PR38-CODEX8-1). `shell-command-guard`, `scheduled-task-mutation-guard`, `database-query-mode-guard`, and the six interpreter-aware operation guards read raw-device, schedule-file, and standard-input redirections from there.
- `mcp-egress-guard` blocks a call to a Youdede MCP server when its arguments name a host outside that server's declared egress. It reads every nested string, URL-like keys such as `url`, `host`, and `baseUrl`, and `scheme://` URLs in free text, and compares WHATWG-normalized hosts exactly, so lookalike, subdomain, userinfo, IP, and punycode forms are refused. `none` refuses every host, `file:` passes only inside the workspace, and an unknown Youdede server is blocked; other MCP servers pass. The egress list comes from each `server.json` through `catalog/mcp-pins.json`, which `npm run mcp` regenerates and `check:mcp` verifies. Claude Code binds `PreToolUse` on every MCP tool; Cursor has a preview `beforeMCPExecution` adapter. `secure-agent-boundaries` 1.2.0 adds it as enforcement for `agent-tool-security`.
- Three bounded workflow commands cover CI diagnosis, redacted environment preflight, and repository-instruction audits; four generated contexts add API, migration, CI, and dependency baselines at precedences 300–600.
- `quality/hook-verdicts.json` records the current verdict of all 64 Claude Code hooks on about 4,400 inputs: the inputs of the hook tests, the audit probes, multi-command sequences, and everyday developer commands and edits. `tests/hook-verdicts.test.mjs` (run by `npm test`) fails on any verdict change that does not declare a `change` with its reason and finding; `npm run hook-verdicts` records new entries and declared changes. Entries whose current verdict is known to be wrong carry an `expectation` naming the finding.
- Preview external MCP profiles pin the official GitHub server `v1.12.2` in read-only reduced-toolset mode and Playwright MCP `0.0.82` in isolated loopback-only mode. They ship in the separate `remote-review-evidence` and `browser-verification` packs rather than widening `mcp-baseline`.
- `scripts/lib/shared-hook/capability.mjs`, a new shared hook module, matches a Bash command against a hook's declared capability (executables, paths, option roles, ordered safe modes, decisive options, dynamic-executable evidence) and answers a concrete rule, uninspectable, or not this hook's. No hook uses it yet. `tests/capability-contract.mjs` validates declarations against a fixture of verified CLI option roles (`tests/cli-options.mjs`), and `scripts/bench-shared-hook.mjs` checks the absolute time budget that `npm test` leaves to a scaling test.
- `scripts/lib/shared-hook/shell-items.mjs`, a new shared shell parser, turns a Bash command into the items it runs, in order: commands with their wrappers, assignments, redirections, and standard-input source; programs known only at run time (network output, command output, variables); and the limits it stops at (depth, size, wrappers, syntax). It expands function bodies at their call sites, static here-documents and `echo`/`printf` feeds into shells, and brace words, all within fixed caps. No hook uses it yet; the old `parseShellCommands` is unchanged. `tests/shared-hook-items.test.mjs` holds its contract, and `quality/hook-verdicts.json` now records all 31 Bash hooks on the 262 commands of `quality/everyday-commands.txt`.

### Changed

- Links between artifacts have three levels, driven by data. Required (`relationships.prerequisites`): the installer asks once per `add` or `add-pack`, default yes, and every kind of artifact installs its missing prerequisites (draft-evidenced-plan now requires coding-style-baseline). Suggested (new `relationships.suggests`): never asked; after an install one line hints at the companions not installed, not in the pack, and available on the target. Related (`composesWith`): catalog only. Every prerequisite and suggestion has a short reason (new `relationships.linkReasons`), which the installer prints, so the shell-command-guard wording is now data; validation fails without one. The advisory prerequisites of audit-repository-instructions, preflight-change-environment, and frame-design-direction became suggestions, and the read-only MCP servers suggest mcp-egress-guard, database-migration-baseline its review skills and migration guard, and diagnose-ci-failure github-readonly. `catalog/artifacts.json` and `catalog/packs.json` move to schema version 2: `links` lists every edge with its kind, reason, and shared targets, `relationshipGraph.linkCounts` counts them, and each pack lists the companions its members suggest (`suggests`); every version 1 field is kept. The link reasons are translated in `catalog/reasons.it.json` and `catalog/reasons.nl.json`. `docs/catalog-format.md` describes the format for the website.
- `tests/hook-verdicts.test.mjs` runs most verdict cases in process through each hook's exported `evaluate` (`scripts/lib/hook-verdict-inline.mjs`), with the case's fixture, environment, and working directory. The cases about the process itself, one case per hook, and the session and compaction hooks still run as hook processes, and a parity sample runs both ways and must agree. `npm run check:hook-verdicts` now runs every case as a hook process, and the release workflow runs it.
- `quality/hook-verdicts.json` stores each case once with a result per hook (schema 2) instead of one entry per case and hook: 2,486 cases and 15,119 results instead of 15,131 entries, 2.7 MB instead of 4.2 MB. The 12 entries that repeated a hook on the same case are merged; their verdicts, expectations, and changes agreed. The recorder and the tests expand the cases in memory (`scripts/lib/hook-verdict-format.mjs`); `scripts/migrate-hook-verdicts-v2.mjs` converted the file, and `tests/hook-verdicts-format.test.mjs` proves the expansion equals the entries it came from.
- Every hook that reads Bash commands now names `shell-command-guard` as a prerequisite, so a command that hides what it runs (`bash -c "$X"`, `curl … | sh`) is stopped even when only, say, `commit-guard` was requested. The installer asks first in a terminal (`commit-guard cannot see hidden commands (e.g. bash -c "$X"): shell-command-guard stops them. Install it too? [Y/n]`), installs it with the same line as a notice elsewhere, and `--no-prerequisites` installs the hook alone. Removing `shell-command-guard` while a hook needs it asks for confirmation in a terminal and is refused elsewhere unless `--force`. `add --dry-run` lists the prerequisite's files. The packs `daily-driver`, `data-change-safety`, `mobile-release-readiness`, `reviewable-change`, and `secure-agent-boundaries` now include `shell-command-guard`.
- The sixteen remaining Bash hooks (`archive-extraction-guard`, `container-privilege-guard`, `firewall-policy-mutation-guard`, `install-lifecycle-script-guard`, `foreground-process-guard`, `release-clean-state-guard`, `release-version-consistency-guard`, `database-query-mode-guard`, `sensitive-file-access-guard`, `outbound-data-guard`, `system-path-mutation-guard`, `user-account-mutation-guard`, `test-integrity-guard`, `migration-safety-guard`, `submodule-target-guard`, `protected-branch-guard`) read commands with the shared item parser and declare a `CAPABILITY`. A word known only at run time blocks only where it can spell what the hook protects, wrappers such as `env -C` and assignment prefixes are read through, and a program the command runs but does not contain is left to shell-command-guard unless its text names what the hook protects. Package runners (`npx`, `pnpm exec`, `bundle exec`, and others) are followed by the hooks that declare them. protected-branch-guard keeps its rules, and still refuses a Git command with a `GIT_DIR`, `GIT_WORK_TREE`, or `GIT_CONFIG*` prefix. database-query-mode-guard still refuses a client that names a SQL file; one without SQL passes.
- The eight hooks that read what a commit will take (`commit-guard`, `commit-signature-intent-guard`, `executable-permission-guard`, `lockfile-origin-guard`, `symlink-publication-guard`, `large-diff-review-guard`, `debug-artifact-guard`, `dependency-change-guard`) use the rewritten `commit-content` module on the shared item parser. Configured Git aliases are followed one level. A commit in the same command as `git add -f`, an alias definition, a shell alias, or an alias of an alias is refused (new rule `commit-sequence-unsupported` in commit-guard, each hook's own rule elsewhere): run them as separate tool calls. `GIT_DIR`/`GIT_WORK_TREE` assignments and `env -C` are scope changes. A program the command runs but does not contain is left to shell-command-guard. dependency-change-guard declares its package-manager rules as a `CAPABILITY`.
- The six operation guards (`package-publish-guard`, `infrastructure-apply-guard`, `cloud-resource-deletion-guard`, `container-registry-publish-guard`, `scheduled-task-mutation-guard`, `system-service-mutation-guard`) declare their commands as a `CAPABILITY` and read commands with the shared item parser, matcher, and the new `inline` module. A program the command runs but does not contain is left to `shell-command-guard`, their prerequisite, so `curl … | sh`, `sh -s < install.sh`, and `echo 'systemctl stop nginx' | sudo sh` no longer block in the guards that do not protect that command; a static feed of a protected command gets the concrete rule. A finding inside an interpreter one-liner is always uninspectable; a capable program that only prints a protected command is refused as well (retained false positive). `yarn`, `hatch`, and `flit publish --dry-run` are refused until each dry run is verified.
- `shell-command-guard` reads commands with the shared item parser and capability matcher. It now owns every program a command runs but does not contain, for itself and for the six operation guards (`package-publish-guard`, `infrastructure-apply-guard`, `cloud-resource-deletion-guard`, `container-registry-publish-guard`, `scheduled-task-mutation-guard`, `system-service-mutation-guard`), which name it in `relationships.prerequisites`: a network program run by a shell is `internet-to-shell`, and any other one (`eval "$X"`, `bash -c "$CMD"`, `eval "$(some-tool emit)"`) is uninspectable. Shell setup output (`eval "$(pyenv init -)"`, `source <(kubectl completion bash)`), local script files (`bash setup.sh`, `cat setup.sh | sh`, `sh < install.sh`), and static feeds (`echo 'npm test' | sh`) pass; `time { … }`, `case` statements, and `env | sort` no longer block as uninspectable; `env -C / rm -rf /` and `PATH=/tmp rm -rf /` block as `broad-filesystem-delete`.
- `add` of a hook installs its missing hook prerequisites first ("Installed prerequisite shell-command-guard …") and removes them again when the hook fails to install; `add --dry-run` lists them. `remove` refuses a hook that an installed hook needs, unless `--force`. Prerequisites of other kinds stay advisory. A hook that is a prerequisite of another hook in a pack no longer counts toward the pack hook fan-out (`pack-info` names it after the count). `pack/release-readiness` 1.2.0 adds `shell-command-guard`.
- Behavioral evaluation cases are written per artifact. The 102 skills that used one "contract simulation" template, and the 18 commands and contexts whose four cases `scripts/generate-prompt-evaluations.mjs` generated from one template, now have a concrete request with its evidence, a near miss that belongs to a neighbouring artifact, a missing or invalid input the payload names, and a boundary that crosses one of the artifact's refusals. Anchors quote the step, refusal, or stop condition each case exercises. Boundary cases expect `decline` when the request itself asks to exceed the artifact's authority and `limit` when only the supplied evidence carries that instruction; 41 subagent and skill boundary prompts that described the instruction in the abstract, or asked the user to obey it while expecting `limit`, now quote it inside concrete evidence, and 13 are now `decline`. Every case of a payload that requires its headings on every path requires all of them. The generator and `npm run prompt-evaluations` are removed; command and context cases are edited by hand like the others.
- The Cursor adapters of `allowlisted-fetch-readonly`, `repository-git-readonly`, and `workspace-files-readonly` are back to `preview`. ADR 0002 requires an MCP egress guard before an MCP server is stable, and the egress guard's Cursor adapter is not yet verified in a live Cursor client.
- Repository validation accepts a Cursor guard adapter on `beforeMCPExecution` without a matcher, besides `preToolUse`, because Cursor documents no matcher value for that event.
- GitHub Copilot skill adapters are now `stable` and name the surfaces GitHub documents for Agent Skills; GitHub's page (read 2026-09-26) has no preview label. Copilot subagent adapters stay `preview` and now name the surfaces where GitHub marks custom agents as public preview: JetBrains IDEs, Eclipse, and Xcode.
- Gemini CLI subagent adapters are now `stable`: the official subagents page (read 2026-09-26) says subagents are enabled by default and no longer calls them preview. Every Gemini CLI adapter, and `docs/targets.md`, now states that Google stopped serving Gemini CLI on 2026-06-18 for free use and for Google AI Pro and Ultra, and that Antigravity CLI, which replaces it for those users, is not a target.
- The npm package no longer contains the `skills/` and `plugins/` marketplace copies, the marketplace manifests, or the README images; native marketplaces read them from the repository. The packed size drops from about 4.8 MB to about 1.4 MB, and the CLI commands behave identically on the extracted package.
- Repository validation rejects a subagent whose body differs between targets, apart from the Copilot turn-budget line.
- Behavioral evaluation coverage now includes every skill, subagent, command, and context. Release benchmark inputs, package verification, readiness counts, catalog documentation, and naming/authoring guidance use the same six-kind model.
- `resume-session-work` is published only for Claude Code. Its Gemini CLI, GitHub Copilot, Cursor, and OpenCode adapters are withdrawn, as the Codex one already was, because the session ledger and its hooks install only for Claude Code; on those runtimes the skill had nothing to read.
- The `mobile-release-readiness` pack summary (1.0.1) states what its release guards stop today: npm, pnpm, yarn, cargo, twine, and `gh release` publication. `fastlane`, `eas submit`, `xcrun altool`, and Gradle publish tasks are not intercepted, and version consistency covers `package.json` and its lockfile, not mobile build numbers.
- Two packs no longer call a subagent that does not verify their outcome a verifier. In `browser-verification` 1.0.1, `web-performance-reviewer` is a specialist and the summary says the change is reviewed for web performance risks, not that the journey is independently re-verified. In `session-continuity` 1.1.0, `decision-record-reviewer` is a specialist mapped to `resumable-work`; `verified-session-history` rests on `verify-session-ledger`, which checks the hash chain.
- Command documentation now states the actual enforcement boundary: deterministic preconditions are a mandatory first prompt action, not a pre-invocation parser supplied by the native slash-command runtime.
- The `plan-and-verify-loop` pack summary (1.1.1) says what its gate does: it validates the order of the phase evidence files under `.youdede/phases/`. No member of the pack writes those files, so implementation was never gated.
- An ambiguous entry of the shared shell analysis carries `segment`, the tokens of the segment it came from, so a hook can judge that segment's text.
- The file-editing hooks of the data, design, and development domains take the project root from `CLAUDE_PROJECT_DIR` when it is set, as `test-integrity-guard` already did. Before, they used the payload `cwd`, which follows Claude after `cd`: after `cd sub`, a migration at the project root was not inspected and an edit to a file outside `sub` could be blocked as unverifiable.
- A `should-allow` or `should-block` expectation in `quality/hook-verdicts.json` is now a gate: `tests/hook-verdict-gate.test.mjs` fails when the recorded verdict contradicts it, unless `quality/hook-verdict-quarantine.json` holds a reviewed entry (hook, reason, follow-up) keyed by the SHA-256 of the case and its expectation. Seven known hook defects are quarantined; three wrong expectations are removed (Python `sqlite3` SQL, which `database-query-mode-guard` does not claim to inspect, a truncated opted-in completion transcript, and a subagent transcript over the declared 4 MiB bound, which both fail closed as documented). `node scripts/record-hook-verdicts.mjs --summary` reports the verdicts changed since a Git revision.

### Fixed

- The situation rules shared by every prompt artifact contradicted themselves: the first test said to decline any request that asked for too much, while a later rule said a reply carrying analysis never declines. The labels are now defined by what the reply contains, so a reply that turns down one request and answers the rest is reduced scope, and bounding a conclusion to the evidence no longer counts as reducing it.
- Two generated contexts stated a forbidding rule as a requirement (`effect=require; action=expand-ci-privilege`, `action=bypass-dependency-safety`) while their text said to block it. The rules are now `block-ci-privilege-expansion` and `keep-dependency-changes-safe`.
- The ten workflow commands and `resume-session-work` now state the same output contract as every other prompt artifact, so their replies can be checked. `check:contracts` used to skip a payload with no contract and now reports it; a context is exempt because it is loaded into every session, and its responses are checked for forbidden assertions only.
- `audit-repository-instructions`, `draft-evidenced-plan`, and `diagnose-ci-failure` declare `Bash`, which their mandatory precondition step needs to run its script.
- `commit-guard` and `prompt-secret-guard` read one shared list of 117 credential formats (`scripts/lib/shared-hook/secret-rules.mjs`), which the repository scan uses too. Both hooks had their own shorter copies (7 rules) and let GitHub fine-grained tokens (`github_pat_`), npm, GitLab, and Google API keys through; every PGP private key block and `ENCRYPTED PRIVATE KEY` header passed all three. The list adds key files (PuTTY, age, Bitcoin extended keys) and the prefixed or fixed-structure tokens of cloud, source-control, registry, CI/CD, observability, messaging, payment, and AI providers, many adapted from the gitleaks default configuration (v8.30.1, MIT, credited in NOTICE) and cross-checked with OpenRouter's published secret formats. Gitleaks rules that depend on a keyword prefilter or entropy, JWTs, bare hex or UUID shapes, and Stripe test keys stay out, because these hooks block with no exception; the Sourcegraph, Vault, and Square patterns drop the alternatives that match any SHA-1 or base64 line. On 128,000 third-party and project files (933 MB) the list matched only private key headers and real-format webhook secrets in test fixtures, and the slowest 5 MB input takes about 0.3 s. A Google key ending in `-` now matches, an Anthropic or OpenRouter key no longer also counts as OpenAI, and commit-guard applies the OpenAI word filter prompt-secret-guard already had.

- `shell-command-guard` now blocks `/bin/rm -rf /`, a force push or remote delete after Git global options (`git -C . push --force`, `git --no-pager push -f`, `git push -uf`), a root among several `rm` operands (`rm -rf ~ /tmp/x`, `rm -rf / --no-preserve-root`), `bash <(curl …)`, `git checkout -f`, `git switch -f`/`--discard-changes`, a push with `-f`, `--force`, or a `+refspec` even when `--force-with-lease` or `--force-if-includes` is also given (Git then force-updates the remote), and destructive commands behind `nice`, `timeout`, `xargs`, `sudo bash -c`, or `if …; then …; fi`. It no longer blocks text quoted inside an argument (`git commit -m "fix; rm -rf /"`) or `[ -f .env ] && …`. Before, the rules matched the raw text with `git push` and `rm` in fixed positions, and each hook carried its own shell lexer.
- `commit-guard` now blocks `git add -f .env && git commit`, commits through Git aliases (configured, defined in the same command, or `git -c alias.<name>=`), `git commit -nm`, `git -c core.hooksPath=… commit`, commits run by `xargs` or `find -exec`, a second commit after `git add` in the same command, and working-tree commits started from a subdirectory; it no longer blocks `[ -f .env ] && …` as uninspectable. ### Changed

- Expanded the catalog to 264 artifacts and seven outcome packs across six coding-agent runtimes.
- Every prompt-bearing artifact now states one unconditional output contract: the headings to return on every path, including when it declines or lacks inputs.
- Behavioral response checking no longer grades a self-reported disposition, and `requiredEvidence` phrases are reported as reviewer advice rather than enforced as literal substrings.
- Forbidden-phrase detection is scoped to the sentence rather than a fixed window, so a refusal or a report of what was requested no longer counts as an assertion. One guard governs every clearing rule: a first-person completed claim after a refusal is still a violation.

### Fixed

- Twelve guards and helper scripts passed their environment straight to `git`, so an inherited `GIT_DIR` made them inspect a repository other than the one they were pointed at, and report the result as if it came from the project in front of them. They now strip every `GIT_*` variable, matching the convention `protected-branch-guard` already used.
- `remove --force` resolved the hook marker from the entry being removed rather than from recorded state, so a forced removal could delete a marker it never installed.
- Concurrent installs shared no lock, and a refused install created a configuration root as a side effect.
- Subagent validation assumed a single target shape and rejected targets that identify an agent by filename.
- Unknown command-line flags were accepted silently.

### Removed

- Authoring research snapshots and origin-tracing records from the publishable repository surface.
