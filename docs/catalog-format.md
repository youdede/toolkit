# Catalog format

`catalog/artifacts.json` and `catalog/packs.json` are generated by `npm run catalog` from the manifests; `npm run check` fails when they are stale. This page describes them for a website or an API, in particular the links between artifacts. Both files are at `schemaVersion` 2. Version 2 only adds fields: every field of version 1 is still present with the same meaning.

## Links between artifacts

An artifact links to another at one of these levels, declared in its `artifact.json` under `relationships`:

| Kind in `links` | Manifest field | Meaning | Installer |
|---|---|---|---|
| `required` | `prerequisites` | It does not work without the other. | Asks once, default yes, to install the missing ones with it. |
| `suggested` | `suggests` | It works, and works better with the other. | After the install, one hint line; never asks. |
| `related` | `composesWith` | Both belong to the same workflow. | Nothing. |
| `conflicts` | `conflictsWith` | They must not be installed together. | Nothing yet. |
| `supersedes` | `supersedes` | It replaces the other. | Nothing yet. |

Every required and suggested link has a short plain-English reason (`relationships.linkReasons`, keyed by the target artifact id, at most 120 characters). A required link's reason is a sentence, shown before the install question. A suggested link's reason completes "add <slug> …" (for example "to check MCP tool arguments against declared egress"), so it starts lowercase and has no final period. Related, conflicting, and superseding links have no reason.

## catalog/artifacts.json

- `artifacts[].relationships` always has every key, in this order: `composesWith`, `conflictsWith`, `supersedes`, `prerequisites`, `suggests`, `linkReasons`, `packIds`. `suggests` and `linkReasons` are new in version 2 (empty when the manifest has none).
- `links` (new) lists every link once, sorted by `from`, then `to`, then kind in the order of the table above. Each edge has `from` and `to` (artifact ids), `kind`, `reason` when the link has one, and `targets`: the targets on which both ends exist (possibly empty for a related pair across targets). Required, suggested, and superseding links are directed. Related and conflicting links are symmetric: each pair appears once, with `from` sorting before `to`.
- `relationshipGraph.linkCounts` (new) counts the edges of each kind; `relationshipGraph.counts.directedEdges` also counts `suggests`.

One edge of each kind:

```json
{"from": "hook/security/secrets/commit-guard", "to": "hook/security/application-security/shell-command-guard", "kind": "required",
 "reason": "commit-guard cannot see hidden commands (e.g. bash -c \"$X\"): shell-command-guard stops them.",
 "targets": ["claude-code", "codex", "cursor", "gemini-cli", "opencode"]}

{"from": "mcp-server/development/testing/playwright-local-isolated", "to": "hook/security/network-control/mcp-egress-guard", "kind": "suggested",
 "reason": "to check browser tool arguments against declared egress (not page requests)",
 "targets": ["claude-code", "cursor"]}

{"from": "command/development/agent-tooling/re-pin-mcp-tools", "to": "hook/security/network-control/mcp-capability-drift-guard", "kind": "related",
 "targets": ["claude-code"]}
```

No artifact declares a conflict or a replacement today; such an edge would look like this (illustrative ids):

```json
{"from": "hook/example/area/new-guard", "to": "hook/example/area/other-guard", "kind": "conflicts", "targets": ["claude-code"]}
{"from": "hook/example/area/new-guard", "to": "hook/example/area/old-guard", "kind": "supersedes", "targets": ["claude-code"]}
```

A page for one artifact can show its outgoing required and suggested links with their reasons ("Requires shell-command-guard: …", "Goes well with mcp-egress-guard: …"), its incoming required links ("Required by …"), and its related artifacts, and filter each list by the target the reader chose.

## catalog/packs.json

`packs[].suggests` (new) lists the companions outside the pack that its members suggest, for "goes well with": `id`, the `reason` of the first member (in id order) that suggests it, and `suggestedBy`, every member that does. A companion the pack already contains is not listed.

```json
"suggests": [
  {"id": "hook/security/network-control/mcp-egress-guard",
   "reason": "to check browser tool arguments against declared egress (not page requests)",
   "suggestedBy": ["mcp-server/development/testing/playwright-local-isolated"]}
]
```

## Translations

`catalog/reasons.it.json` and `catalog/reasons.nl.json` translate the user-facing reasons into Italian and Dutch: `reasons` by artifact slug (`risk`, `latency`), and `links` by the slugs of the two ends:

```json
"links": {
  "commit-guard": {"shell-command-guard": "commit-guard non vede i comandi nascosti (ad es. bash -c \"$X\"): shell-command-guard li blocca."}
}
```

`sourceHash` is the SHA-256 of every English source reason (artifact and link). `npm run check:reason-translations` fails when a translation is missing, equals its English source, names an unknown artifact or link, or when `sourceHash` no longer matches the sources, so an edited English reason cannot ship with a stale translation.
